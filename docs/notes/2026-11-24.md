# 2026-11-24

## Where things stood

0.5.2 was in review on WordPress.org. The counts were in two tables,
`_daily` and `_referrers`.

## What was done

- 0.6.0: one table, `{prefix}nhrrob_post_insights`, with a `kind` per row
  (`post`, `host`) and an `item` (empty, or the host). `Installer` moves the
  rows of the two old tables in on the first load after the update and drops
  them. Every read in `Store` names its kind. Another plugin can keep its own
  kind of counter in the same table. See [DECISIONS.md](../DECISIONS.md).
- Checked on the dev site: the old rows moved over with the same sums, the
  old tables are gone, `/stats` and `/posts` answer as before, and the smoke
  test passes.

- Robin chose to keep one table (no tables would mean racy counts and slow
  dashboards on post meta), and asked for read functions so the blog and
  NHR Social Share stop querying the table: `Read` in 0.6.0.

## Left open

- The submitted 0.5.2 still has two tables. After approval, release 0.6.0
  to WordPress.org as usual.

## Release on a tag

- The tag push now also makes the GitHub release (a second job in
  `deploy-on-pushing-a-new-tag.yml`), so a release is only `git tag` and
  `git push` of the tag. Robin's request, the same in every plugin.
